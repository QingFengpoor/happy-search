# 开心连连看（Lianliankan）— 部署文档

移动端优先的 HTML5 消除小游戏，纯前端实现（HTML + CSS + 原生 JS，零依赖、零构建），支持 PWA 离线安装到手机桌面。

- 当前版本：**v25**（日志与缓存标记一致）
- 技术栈：HTML5 / CSS3（oklch 色彩、CSS 变量、媒体查询断点）/ 原生 ES Module JavaScript / Service Worker PWA
- 运行环境：任何静态文件服务器（Nginx、Apache、GitHub Pages、Vercel、对象存储静态网站等）

---

## 一、需求说明

### 1.1 产品定位

轻量休闲消除小游戏，单页应用，点开即玩，可安装到桌面离线运行。

### 1.2 功能需求

| 模块 | 需求 |
| --- | --- |
| 普通连连看 | 点选两个相同图案，连线转弯 ≤ 2 次即可消除；限时 / 休闲两种节奏；6 个递进关卡 + 星级评定 + 逐关解锁 |
| 特殊方块 | 🪨 石头（障碍挡线）、🧊 冰冻（消相邻一对解冻）、🌈 彩虹（百搭配对）、⏰ 时钟（限时 +15 秒） |
| 克制消除 | 7 关闯关，每关一组闭环克制链；只能点相克的一对，被克者消失、克制者留下继续吃（链式）；无相克对时和平收场；逐关解锁；克制链常驻显示且暂停时不被遮挡 |
| 闯关无尽 | 每轮时限 = 12 秒缓冲 + 每对 4 秒；清完一轮把"盘面应得时间"存入时间银行（可累积）；棋盘逐轮变大、特殊块逐轮增多 |
| 生存无尽 | 盘面 7×7 恒定；消除一对原地随机补充一对；每对 +4 秒（可累积）；每 15 对 +1 图案（上限 12）、每 15 对奖时 −0.2 秒（下限 2.0）；连击窗口 10 秒；提示半价 |
| 系统 | 三套主题（水果/甜品/动物）、音效开关（Web Audio 合成）、暂停 / 继续、提示（−20，生存 −10）、手动洗牌、PWA 离线、运行日志面板（复制/导出）、调试探针 |

### 1.3 非功能需求

- 移动端优先：单手操作，触屏友好，安全区适配（`viewport-fit=cover` + `env(safe-area-inset-*)`）
- 多端自适应：手机竖屏 / 手机横屏 / 平板 / PC，断点式布局（见设计说明）
- 性能：单文件 JS 约 1600 行，无框架运行时，首屏 < 20KB（不含图标）
- 可维护：结构化常量配置（关卡表、克制表、主题表集中定义，可调参）
- 可诊断：内置环形日志（localStorage 持久化，300 条），带版本号便于核对玩家端版本

## 二、设计说明

### 2.1 棋盘与寻路

- 内部棋盘为 `(rows+2) × (cols+2)`，最外圈恒为空，作为连线的"外围通道"
- 连通判定：BFS  over `(行, 列, 方向)`，转弯次数 ≤ 2（连连看经典规则）
- `passable(v)` 只有空格可穿过——石头/冰冻/图案一律挡线，连线必须从外围绕行
- 连通即消除，与两格之间的图案无关（彩虹规则例外：可与任意图案配对）

### 2.2 计数与终局（remainPairs）

- 图案按"对"计 1 单位；冰冻/彩虹/时钟各计 1 单位
- 消除一对 −1；解冻冰冻 −1；强制清盘按残留类型扣减
- 通关唯一条件：计数归零。生成时保证每种图案张数为偶数（杜绝孤儿牌），特殊块成对覆盖同种图案的一对格子（防止覆盖后产生单张）
- 死局恢复：检测无解 → 重排剩余（最多 50/100/200 次）→ 仍无解才强制清盘并记日志
- 冰冻块若四邻全被堵死（永远等不到相邻的一对），标记 `noThaw`，残局走强制清盘，避免无限无解重试

### 2.3 克制消除规则

- 每关一组**单一闭环**克制链：`A 克 B 克 C …… 最后克回 A`，每个元素克下一个、被上一个克
- 点选后只能点"被克者"完成吃子：被克者消失，克制者留在原位并保持选中，可继续吃下一家（链式吃子）
- 收官条件：剩 1 子（无法被吃）/ 只剩一种元素 / 剩余元素互不相克（和平收场）
- 每关各元素数量相等（数量相等 ⇒ 任意局面必有相克对，理论上不存在死局；实测 7 关全部自动通关验证）

### 2.4 无尽模式时间经济

| 模式 | 经济模型 | 难度递增 |
| --- | --- | --- |
| 闯关无尽 | 每轮时限 = 12 秒 + 每对 4 秒；清完一轮把"盘面应得时间"（格数 × 4 / 2）存入银行，剩余时间不清零 | 棋盘 48→56→72→80 格循环变大；特殊块每轮 +2（上限 14） |
| 生存无尽 | 开局 42 秒；每对 +4 秒（无封顶，可无限累积） | 每 15 对 +1 图案（6→12 封顶）；每 15 对奖时 −0.2 秒（4.0→2.0 下限）；平衡速度 0.8→1.0~1.2 秒/对，快手续命、慢手体面结束 |

### 2.5 连击与计分

- 连击窗口 10 秒（生存模式找对成本高，宽窗口避免分数断崖）
- 每对基础 10 分，连击每级 +5（x1=10, x2=15, x3=20 …）
- 通关时间加成：剩余秒数 × 2

### 2.6 多端自适应（CSS 断点）

| 断点 | 布局 |
| --- | --- |
| 默认（手机竖屏） | 单列：HUD → 棋盘 → 底部工具栏，`.screen` max-width 520px |
| ≥700px 且 高度 ≤519px（横屏手机/矮窗口） | HUD 压缩：计时条 14px、分数 20px、按钮 44px |
| ≥900px 且 高度 ≥520px（平板/PC） | 左右分栏：棋盘居左（flex 1.6），HUD 卡片 + 工具栏合成右侧栏（max-width 360px），格子上限放宽到 92px |
| ≥1440px 且 高度 ≥900px（大屏） | 格子上限 110px，字号上调 |

`layoutBoard()` 在每次开局/窗口变化时读取 CSS 变量 `--cell-max`，按容器实际尺寸（content-box）计算格子大小与留白，保证棋盘始终不溢出。

## 三、系统架构

### 3.1 目录结构

```
├── index.html            页面结构：标题页（模式/关卡/主题/日志面板）+ 游戏页（HUD/棋盘/工具栏）+ 遮罩
├── manifest.webmanifest  PWA 清单（名称/图标/主题色/standalone 显示）
├── sw.js                 Service Worker：main.js 网络优先（保证代码即时更新），其余资源缓存优先
├── icons/                192 / 512 PNG 图标（含 maskable）
├── src/
│   ├── main.js           全部游戏逻辑（约 1640 行，ES Module，无依赖）
│   └── style.css         全部样式（oklch 色彩系统、CSS 变量、断点布局、动画）
└── README.md             本文件
```

### 3.2 模块划分（main.js 内聚结构）

```
配置区      LEVELS / PSR_LEVELS / THEMES / ENDLESS / STONE/FROZEN/RAINBOW/CLOCK 常量
日志系统    glog() 环形缓冲 + localStorage 持久化 + 导出/复制/下载 + 关键事件过滤
存档        loadSave()/persist()：llk_save_v1（解锁进度、星级、最佳分、主题、音效、模式、生存最佳）
音效        Web Audio 振荡器合成（点击/选择/消除/连击/胜负），无音频文件
寻路        findPath() BFS ≤2 弯；passable() 仅空格可穿；dominates() 克制判定；findMove()/findAnyPair()
棋盘        setupBoard() 成对生成+特殊块成对覆盖；reshuffleRemaining() 死局重排；boardUnits() 计数
渲染        renderBoard()/paintTile()/syncTile() 双模式（主题 emoji / 克制 emoji）；layoutBoard() 自适应
交互        onTileTap() 分支：普通消除 / 克制吃子 / 生存补充；useHint()/useShuffle()
流程        startLevel/startEndless/startSurvival/startPsrRound + 过关/失败/暂停/恢复遮罩
探针        window.__llk：G 状态、findMove、getLog、startXxx —— 供自动化测试与现场诊断
```

### 3.3 数据流（一次消除）

```
点击格子 → onTileTap(r,c)
  ├─ 未选中 → 记录选中态
  ├─ 已选中 → 判定可消除（同图案/彩虹/克制）→ findPath 连通？
  │   ├─ 否 → 改选 + 抖动反馈
  │   └─ 是 → 锁定输入 → 连击/计分/日志 → 清两格
  │         → 冰冻解冻检测（去重 + noThaw 标记）→ 300ms 动画
  │         → 生存模式：原地补充 + 奖时 + 难度递增 + 计数恒定
  │         → 普通模式：计数 −1 → 归零？过关 : 无解？重排/强清
  │         → 克制模式：被克者消失、克制者留选 → 收官判定
  └─ 解锁输入 → updateHud()
```

### 3.4 存档与持久化

| 键 | 内容 |
| --- | --- |
| `llk_save_v1` | `{v:1, unlocked, stars{}, bestScore{}, bestEndless, bestSurvival, muted, mode, theme, psrUnlocked}` |
| `llk_log_v1` | 最近 300 条运行日志（重启不清，便于玩家贴日志反馈） |

存档向后兼容：缺字段自动补默认值（如旧档无 `psrUnlocked`/`bestSurvival` 自动初始化为 1/0）。

### 3.5 PWA 与缓存策略

- `sw.js`：**全部资源网络优先**——联网时总是先取服务器最新内容并顺手更新缓存，取不到（离线 / 服务不可用）才回落缓存
- 只接管同源 GET 请求；跨源请求交给浏览器默认处理
- 每次发版同时递增 `BUILD`（main.js）与 `CACHE`（sw.js）——缓存名变化触发 `activate` 时清理旧缓存，避免新旧代码混跑

> **为什么不缓存优先**（v24 修正）：旧版把 `index.html`、`style.css` 设为缓存优先，而联网时 `fetch` 永远成功，缓存就永远不更新——已安装 PWA 的玩家会永久停在旧页面，改了 HTML 结构或样式他们看不到。本站部署延迟最多 2 分钟，网络优先的额外开销可以忽略，换来的是"发版必定生效"。

## 四、部署指南

### 4.1 要求

任意静态文件服务器。无后端、无数据库、无构建步骤。需要 HTTPS（或 localhost）才能启用 Service Worker / PWA 安装。

### 4.2 本地运行

```bash
cd 项目目录
python3 -m http.server 8080
# 浏览器打开 http://localhost:8080
```

### 4.3 部署到自己的网站

本游戏以**子路径**形式发布在个人站 `jinshui.fun` 下，线上地址 <https://jinshui.fun/game/>。

部署位置是站点仓库的 `site/public/game/`（Astro 的 `public/` 目录会原样拷进构建产物，不需要改 CI 或服务器配置）。同步时把这五个条目整体拷贝过去，保持同一目录层级：

```
site/public/game/
├── index.html
├── manifest.webmanifest
├── sw.js
├── icons/
└── src/
```

**子路径部署注意点**：

- 所有引用都是相对路径（`./src/main.js`、`./sw.js`、`./icons/...`），放在 `/game/` 下无需改动
- `sw.js` 注册作用域默认等于其所在路径，即 `/game/`，不会干扰站点其他页面
- **不要**把 `sw.js` 的作用域提高到站点根目录，否则其他页面会被游戏的缓存策略接管
- 服务器需正确返回 `Content-Type`：`.js` → `text/javascript`，`.webmanifest` → `application/manifest+json`（Caddy / Nginx 默认即可）
- PWA 安装要求 HTTPS（线上满足）或 localhost

**独立部署到根目录**（例如单独域名 `https://你的域名/`）同样可行：把这五个条目放到站点根目录即可，无需任何额外配置。

**SPA 路由**：本应用是单页应用，但所有路由都是相对路径的文件引用，无 history 路由，静态服务器开箱即用，无需 rewrite 规则。

### 4.4 自定义调整（改参数即可，无需改逻辑）

| 想改什么 | 改哪里 |
| --- | --- |
| 普通关卡难度 | `LEVELS` 数组（cols/rows/kinds/time/special/target） |
| 克制关卡内容 | `PSR_LEVELS` 数组（icons/names/beats 闭环链/cols/rows/time） |
| 主题图案 | `THEMES` 数组（换 emoji 即可） |
| 生存难度 | `startSurvival()` 内开局参数 + 消除回调里的难度递增阈值 |
| 闯关无尽经济 | `ENDLESS.buffer` / `ENDLESS.pairTime` |
| 连击窗口 | `COMBO_WINDOW`（毫秒） |
| 提示扣分 | `HINT_COST`（生存模式固定 −10） |
| 时钟加时 | `CLOCK_BONUS` |

## 五、调试与诊断

### 5.1 运行日志（玩家侧）

标题页底部「运行日志」面板：刷新 / 复制 30 条 / 复制 50 条 / 关键事件 / 全部 / 导出 txt / 清空。「棋盘生成」行尾带版本号（当前 v25），一眼确认玩家跑的是不是最新代码。

日志格式：`#序号 时间 [对局标签] 事件 | 详情 · 计数=N · 分=M`

### 5.2 调试探针（开发侧）

控制台执行 `window.__llk` 可访问：

```js
__llk.G            // 全部游戏状态（棋盘/分数/倒计时/模式标志）
__llk.findMove()   // 当前一个可消除对（含路径）
__llk.psrState()   // 克制模式：剩余种类 + 一个可连通克制对
__llk.boardUnits() // 盘面计数
__llk.getLog()     // 全部日志
__llk.startLevel(3) / startPsrRound(5) / startEndless() / startSurvival()
```

### 5.3 自动化测试示例（Playwright）

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    page = p.chromium.launch().new_page()
    page.goto("http://localhost:8080")
    page.evaluate("__llk.startPsrRound(1)")
    # 自动打一局：循环取提示对并点击
    while True:
        if page.evaluate("!document.getElementById('overlay').hidden"):
            break
        st = page.evaluate("__llk.psrState()")
        if not st["pair"]: continue
        a, b = st["pair"]["a"], st["pair"]["b"]
        page.evaluate(f"__llk.onTileTap({a[0]},{a[1]})")
        page.evaluate(f"__llk.onTileTap({b[0]},{b[1]})")
        page.wait_for_timeout(350)
```
